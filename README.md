# Scale Institutional Knowledge Using Copilot Spaces

This repository is a practical GitHub Skills exercise for scaling institutional knowledge using GitHub Copilot Spaces. The goal is to centralize key project and operational knowledge so teams can onboard faster, make decisions with context, and keep execution consistent across time and teammates.

## Why this repository exists

As teams grow, knowledge often gets scattered across chat threads, issue comments, spreadsheets, and tribal memory. This project demonstrates a simple pattern for capturing repeatable project processes in a single, discoverable place.

The documents in this repo model a lightweight project management framework for OctoAcme, including:

- project initiation
- planning
- execution and tracking
- release and deployment
- risk and communication
- retrospectives and continuous improvement
- roles and personas

## Repository structure

- `README.md` — project overview and guidance
- `docs/` — reusable project management and operational templates
- `.github/` — repository automation and exercise metadata

### Document set

- `docs/octoacme-project-management-overview.md` — high-level view of the operating model
- `docs/octoacme-project-initiation.md` — how to validate a new project or idea
- `docs/octoacme-project-planning.md` — scope, milestones, dependencies, and planning structure
- `docs/octoacme-execution-and-tracking.md` — how to run and monitor delivery work
- `docs/octoacme-release-and-deployment.md` — release readiness and deployment practices
- `docs/octoacme-risks-and-communication.md` — communication and risk handling
- `docs/octoacme-retrospective-and-continuous-improvement.md` — learning and improvement loop
- `docs/octoacme-roles-and-personas.md` — responsibilities and stakeholder mapping

## Prerequisites

Before using this repository, make sure you have:

- a GitHub account with access to the repository
- GitHub Copilot enabled for your organization or user account
- access to Copilot Spaces or the ability to create and manage space-based knowledge
- a project or team context you want to document and share

## Recommended workflow

Use the repository as a playbook for a project lifecycle:

1. Start with `docs/octoacme-project-initiation.md` to confirm the problem, stakeholders, and success criteria.
2. Move into `docs/octoacme-project-planning.md` to define the roadmap, backlog, milestones, and dependencies.
3. Use `docs/octoacme-execution-and-tracking.md` during delivery to track progress, blockers, and decisions.
4. Review `docs/octoacme-risks-and-communication.md` to keep stakeholders informed and escalate issues early.
5. Finish with `docs/octoacme-retrospective-and-continuous-improvement.md` to capture lessons learned and improve the process.

## Learning objectives

This exercise helps you practice:

- capturing team knowledge in a reusable format
- standardizing project operating practices
- making project context easier to discover and understand
- using GitHub Copilot Spaces to centralize institutional knowledge
- creating a durable project memory for current and future team members

## Using Copilot Spaces effectively

For the best experience, keep the project documentation in a central location that Copilot Spaces can read and reference. A good pattern is:

- store operational docs in `docs/`
- keep project-specific context and working notes easy to update
- use clear headings, consistent terminology, and concise summaries
- update docs as the project evolves instead of letting them become stale

## Contribution guidelines

When contributing to this repository:

- keep documentation clear and scannable
- prefer plain language and actionable guidance
- update related docs when a process changes
- ensure examples remain realistic and easy to adapt
- keep the project knowledge structured and shareable for new contributors
